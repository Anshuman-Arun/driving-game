# Cross-workstream interface contract v1

This contract is fixed for the initial parallel workstreams. Do not silently change it in a feature branch. If an incompatible change is unavoidable, document it in that branch's PR as a proposed v2 rather than updating this shared file.

## Coordinates and units
- Godot 3D world coordinates, +Y up; meters, km/h for displayed speed.
- Map envelope X and Z from -1000 to +1000 meters; road and map coordinates are [x, y, z] arrays.
- Terrain height is a function of (x,z) and must be compatible with road collision. The runtime may offset/localize world coordinates later behind an adapter.

## Road graph JSON — `data/world/road_graph_v1.json`
This file is authored/generated by the World Agent only. Consumers load it; they must not edit it.

Required top-level shape:
```json
{
  "schema_version": 1,
  "units": "meters",
  "coordinate_system": "godot_y_up",
  "bounds": {"min_x": -1000, "max_x": 1000, "min_z": -1000, "max_z": 1000},
  "roads": [{"id": "r1", "name": "Cedar Loop", "region": "cedar_woods", "lane_ids": ["l1", "l2"]}],
  "lanes": [{
    "id": "l1",
    "road_id": "r1",
    "points": [[0.0, 10.0, 0.0], [20.0, 10.1, 0.0]],
    "width_m": 3.5,
    "speed_limit_kph": 60,
    "surface": "asphalt",
    "next_lane_ids": ["l3"]
  }]
}
```
Rules: every ID is unique within its collection; each lane has >= 2 points, no consecutive duplicate points, a nonnegative speed limit, and references only defined road/lane IDs. `next_lane_ids` is directed. Lanes are centerlines, not collision meshes. Connections should meet closely with compatible headings; traffic must not leap across discontinuities. Include bidirectional driving corridors as separate directed lanes, when intended. File must parse as JSON with no engine-only types.

**The World Agent owns this file.** Until it is merged, Racing and Traffic Agents use their own miniature fixtures matching this exact schema.

## Race event JSON — `modules/racing/fixtures/events_v1.json`
The Racing Agent owns the event fixture and a reusable event loader/parser. Later integration may move canonical event data into `data/races/`, but not in parallel branches.
Suggested event shape:
```json
{"schema_version":1,"events":[{"id":"ridge_sprint","kind":"sprint","lane_route":["l1","l3"],"start_position":[0,10,0],"checkpoints":[{"id":"c1","center":[20,10,0],"radius_m":8}],"laps":1}]}
```
Race order and checkpoints must be verified. Race events do not own global input, scene routing, vehicle physics, or `project.godot`.

## Runtime adapters
- Vehicle/engine Agent owns `project.godot`, `addons/`, `scenes/` and `scripts/vehicle/` until initial P0/P1 PR merges.
- World Agent owns `worldgen/` and `data/world/` only. Generates importable data, not changes to the root Godot scene.
- Racing Agent owns `modules/racing/` only. Must expose `load_road_graph(Dictionary)` and `start_event(Dictionary)` or document an equivalent narrow API; standalone demo and tests live in its module.
- Traffic Agent owns `modules/traffic/` only. Must expose `load_road_graph(Dictionary)` and a step/update API and enable deterministic unit-like tests. Standalone scene can use placeholder meshes.
- Art Agent owns `assets/curated/` and `tools/asset_pipeline/` only. Reuse content under a recorded valid license, provide a machine-readable manifest and import hints; do not edit global asset register.

## Shared no-conflict rules
Only the lead/integrator should modify `README.md`, `AGENTS.md`, `docs/PROJECT_STATUS.md`, `docs/ASSET_LICENSES.md`, `docs/TECHNICAL_ARCHITECTURE.md`, `docs/INTERFACES_V1.md`, `project.godot` (except vehicle agent), or other agents' ownership paths while these branches run. If needed, include proposed modifications in `<owned-path>/INTEGRATION_NOTES.md`. No agent merges its own PR into main.

## Validation
Validate JSON against this contract; produce fixtures and deterministic checks. Agent may run headless Godot or Python tests if the runtime is available, but must not claim actual visual, driving or controller tests without real execution.
